# Traveling Scholars Document and Export System Plan

This document is planning only. It does not add backend code, PDF generation, databases, APIs, authentication, storage, environment variables, or dependencies.

## Purpose

The future document engine should help parents turn saved homeschool records into clear, polished, parent-reviewed documents without implying that Traveling Scholars is an accredited school, transcript authority, legal advisor, or curriculum provider.

Documents should feel professional, printable, and trustworthy while keeping parent responsibility explicit.

## Document System Principles

- Generate documents from saved parent-controlled records.
- Let parents review every important field before export.
- Keep document language accurate and non-misleading.
- Store generated documents privately.
- Use consistent branding without making documents look like school-issued credentials.
- Support mobile preview and download.
- Design for future verification without exposing private student data.

## MVP Exports

The first export system should stay narrow.

MVP document types:

- Transcript draft preview.
- Transcript PDF export if generation is stable.
- Basic homeschool certificate PDF.
- Grade report PDF.

MVP non-goals:

- No public verification URLs.
- No public student showcase exports.
- No official school seals.
- No diploma-style claims.
- No state-specific compliance guarantees.
- No batch exports.
- No printed fulfillment.

## Premium Exports

Premium or later document types:

- Family ID.
- Source record IDs.

- Generated timestamp.

Create a parent-reviewed homeschool transcript record from student profile, school year, course, grade, credit, and GPA data.

### Required Source Fields

Student:

- First name.
- Last name.
- Optional preferred name.
- Optional graduation year.
- Optional graduation date.

Family/parent:

- Family name.
- Optional parent name.
- Parent responsibility acknowledgement.

Courses:

- Course title.
- School year.
- Credit value.
- Final grade.
- Grade points.
- Included on transcript flag.
- Course sort order.

GPA:

- GPA type.
- Total credits.
- Total grade points.
- Calculated GPA.
- Calculation timestamp.

### Suggested Layout

Page structure:

- Header:
  - Student name.
  - Document title: Homeschool Transcript Record.
  - Optional graduation year/date.

  - Student details.
  - Family/parent line if enabled.
- Course table:
  - Grouped by school year.
  - Course title.
  - Credits.
  - Grade.
- GPA summary:
  - Total credits.
  - GPA.
  - Grading scale note.
- Parent notes:
  - Optional text.
- Footer:
  - Generated date.
  - Parent-created transcript wording.
  - Traveling Scholars branding.

### Export Formats

MVP:

- PDF.
- Browser preview.

Later:

- CSV course export.
- Print package.
- Verification summary page.

### Parent Customization Options

MVP:

- Include/exclude course.
- Edit parent notes.
- Choose graduation date.
- Choose whether family name appears.

Premium:

- Template selection.
- Section ordering.
- Accent color.
- Custom grading scale display.
- Watermark settings.

### Trust and Safety Wording

Suggested wording:

`Parent-created homeschool transcript record prepared by the family using Traveling Scholars. Parents remain responsible for curriculum, instruction, record accuracy, and homeschool compliance.`

- `Official accredited transcript`.
- `Issued by Traveling Scholars School`.

## Print-Friendly Design Requirements

All document templates should:

- Use high-contrast text.
- Avoid tiny fonts.
- Avoid large ink-heavy backgrounds.
- Use stable margins.
- Support US Letter first.
- Support print preview.
- Avoid interactive-only UI elements in exported documents.
- Keep page breaks controlled.
- Include generated date.
- Preserve document title and student name on page one.

Recommended document sizes:

- Transcript: US Letter portrait.
- Certificate: US Letter landscape or portrait.
- Student ID: card layout on US Letter sheet.
- Attendance report: US Letter portrait.
- Grade report: US Letter portrait.
- Portfolio summary: US Letter portrait.

## PDF Export Considerations

Server-side PDF generation is recommended for production.

Reasons:

- Consistent rendering.
- Better audit logging.
- Private storage.
- Easier watermarking.
- Easier future verification.
- Less device/browser variation.

PDF requirements:

- Embed fonts or use reliable system-safe fonts.
- Generate deterministic output from saved records.
- Include export ID metadata.
- Store export status.
- Store file checksum where possible.
- Keep generated files private.
- Expire download URLs.

## Mobile Download and Share Considerations

Mobile users should be able to:

- Preview documents.
- Download PDF.
- Share using mobile OS share sheet later.
- Regenerate after edits.
- See clear file names.

Recommended file names:

- `student-name-transcript-2026.pdf`
- `student-name-certificate-reading-milestone.pdf`
- `student-name-attendance-2026-2027.pdf`
- `student-name-grade-report-2026.pdf`

Mobile UX:

- Keep export confirmations short.
- Show document type and student name before download.
- Avoid forcing parents to inspect dense preview tables on a phone.
- Offer `Download PDF` and later `Share` as separate actions.

## Future Verification URL Concepts

Verification should wait until privacy, consent, and security requirements are settled.

Possible future model:

- Each final export receives a verification ID.
- Verification URL shows limited metadata only.
- Parent chooses whether a document can be verified.
- Verification page never exposes grades or private records by default.
- Verification can be revoked.

Possible public verification fields:

- Document type.
- Student initials or masked name.
- Generated date.
- Issuing family name if parent allows.
- Document status: valid, revoked, expired.

Do not expose:

- Full transcript content.
- Full birth date.
- Address.
- Portfolio files.
- Private notes.

## Generation Flow Recommendation

### Client-Side Generation

Use only for:

- Lightweight previews.
- Non-authoritative draft rendering.
- UI-only layout previews.

Avoid for:

- Final PDF exports.
- Sensitive files.
- Verification-linked documents.
- Watermarked documents that require audit trails.

### Server-Side Generation

Recommended default for MVP exports.

Flow:

1. Parent requests export.
2. Server validates auth, family access, student access, and plan entitlement.
3. Server loads saved records.
4. Server creates document snapshot.
5. Server generates PDF.
6. Server stores file privately.
7. Server records export metadata.
8. Parent receives signed download URL.

### Queued/Background Generation

Recommended when:

- Exports take more than a few seconds.
- Batch exports are introduced.
- Portfolio bundles include files.
- Verification IDs need post-processing.
- Email notification is needed after completion.

Flow:

1. Parent requests export.
2. Server creates `document_exports` record with queued status.
3. Background worker generates file.
4. Worker stores file and updates status.
5. Parent sees ready state or receives notification.
6. Download uses signed URL.

## Export Permissions

MVP rules:

- Parent owner can export records for students in their family.
- Exporting final PDFs may require paid plan.
- Parent responsibility acknowledgement is required before transcript export.
- Student records must never be fetched by document ID alone.

Later rules:

- Additional parent role may export if owner allows.
- Co-op roles cannot export family transcripts by default.
- Student role can view/download only parent-approved documents.

## Notifications and Reminders

MVP concepts:

- Transcript draft ready.
- Export completed.
- Export failed.
- Missing grades before transcript export.
- Plan upgrade needed for export.

Premium concepts:

- Batch export completed.
- Verification link viewed.
- Export link expiring soon.
- Portfolio bundle ready.

Notification safety:

- Do not include grades or sensitive records in notification text.
- Use general wording and link back to authenticated app.

## Document Trust Checklist

Before any export system ships:

- Parent-created wording appears on transcripts.
- Certificate wording avoids credential claims.
- Student ID wording avoids school-enrollment claims.
- Exports require authenticated access.
- Download links expire.
- Export events are logged.
- Generated files are private.
- Parent can regenerate after edits.
- Privacy policy covers real document generation.
- Terms cover parent responsibility and document limitations.
